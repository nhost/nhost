# Agent guide

This is a full-stack Nhost project generated by `nhost create`. Read this before making changes.

## Stack

- **Backend** (`backend/`): an Nhost project — authentication, a PostgreSQL database, a GraphQL API, storage, and serverless functions. Configured by `backend/nhost.toml`, with database migrations, GraphQL metadata, and functions tracked in source.
- **Frontend** (`frontend/`): a Next.js 16 app (App Router, `src/app`) with React 19, TypeScript, Tailwind CSS v4, and shadcn/ui (new-york style). It talks to the backend through `@nhost/nhost-js`.

## Directory layout

```
backend/
  nhost/
    migrations/   database migrations (SQL)
    metadata/     GraphQL API metadata (tracked tables, relationships, permissions)
    seeds/        optional seed data
  functions/      serverless functions
  nhost.toml      backend configuration
  .secrets        local secrets (never commit real secrets)
frontend/
  src/app/        App Router pages (server components by default)
  src/components/ shared and shadcn/ui components
  schema.graphql  committed GraphQL schema used by codegen
  src/gql/        committed generated GraphQL types and documents
  src/lib/nhost/  the Nhost client wiring for server components and the proxy
  src/proxy.ts    refreshes the auth session on every request
.mcp.json         wires the Nhost MCP server (cwd ./backend)
```

## Key commands

Backend (run inside `backend/`):

- `export NHOST_PROJECT_NAME=<this project>` — set once per shell so the local stack (containers + database volume) stays isolated from your other Nhost projects; `nhost up`/`down`/`logs` all read it. Without it, every project in a `backend/` folder shares one Docker volume.
- `nhost up` — start the local backend (database, auth, GraphQL API, storage). Sign-in emails are captured by the local mail viewer rather than sent.
- `nhost down` — stop it.

Frontend (run inside `frontend/`):

- `cp .env.example .env.local` — once, before the first run.
- `pnpm install`
- `pnpm dev` — start the dev server on <http://localhost:3000>.
- `pnpm codegen` — refresh `schema.graphql` and `src/gql/` after a backend schema change (requires the local backend).
- `pnpm lint` / `pnpm format` — Biome.
- `pnpm build` — production build. This does not require a running backend; pages that reach the backend are dynamic and tolerate it being down.

## Conventions

- **Server components by default.** Pages that read the session or query data are server components and set `export const dynamic = 'force-dynamic'`.
- **The Nhost client is created per request.** Use `createNhostClient()` from `@/lib/nhost/server` inside server components and server actions. It reads and writes the session through Next.js cookies.
- **Auth is cookie-based.** The session cookie is refreshed in `src/proxy.ts` on every matched request, so both server and client components see a fresh session.
- **Protected routes redirect on the server.** A server component reads the session and calls `redirect('/signin')` when there is none; `src/proxy.ts` adds a second guard for the same routes.
- **Sign-in uses email one-time codes.** Request a code with `nhost.auth.signInOTPEmail({ email })`, then verify it with `nhost.auth.verifySignInOTPEmail({ email, otp })`. A user is created the first time an email is used.
- **Network calls are wrapped in try/catch** so the UI degrades gracefully when the backend is down.
- **Absolute imports** via the `@/` alias. Class names are merged with `cn()` from `@/lib/utils`.

## Adding a table and querying real data

The starter includes a `public.todos` table with per-user permissions as a working example.

1. Create another table with a migration under `backend/nhost/migrations`.
2. Track the table and set up relationships and permissions in the GraphQL metadata under `backend/nhost/metadata`.
3. Apply the changes to the running backend (`nhost up` applies pending migrations and metadata).
4. Run `pnpm codegen` inside `frontend/` so `schema.graphql` and the generated types in `src/gql/` reflect the change.

## MCP server

`.mcp.json` registers the `nhost` MCP server (`nhost mcp start`, with its working directory set to `./backend`). It lets an assistant inspect the project's GraphQL schema and metadata and run queries. After changing the schema, list the MCP resources again so the assistant picks up the new schema.
