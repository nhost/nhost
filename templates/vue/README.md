# Nhost + Vue (Vite) starter

A full-stack starter generated by `nhost create`: an Nhost backend (auth, PostgreSQL, GraphQL API) and a Vite + Vue 3 single-page app wired to it, with email one-time-code sign-in, a typed per-user todos feature, and GraphQL code generation.

- `backend/` — the Nhost project: migrations, metadata, functions, secrets.
- `frontend/` — the Vite + Vue app, talking to the backend through `@nhost/nhost-js`.

## Prerequisites

- [Node.js](https://nodejs.org) >= 20 and [pnpm](https://pnpm.io)
- The [Nhost CLI](https://docs.nhost.io/getting-started/local-development/cli) and Docker (for `nhost up`)

## Run it

Start the backend in one terminal:

```sh
cd backend
export NHOST_PROJECT_NAME=my-app
nhost up
```

Start the app in another terminal:

```sh
cd frontend
cp .env.example .env
pnpm install
pnpm dev
```

Open <http://localhost:5173>. The home page runs a live connectivity check. Sign
in with your email; while running locally the one-time code is captured by the
local mail viewer (see the URLs printed by `nhost up`) rather than sent. After
signing in, open the protected page and add a todo — rows are scoped to your
user by GraphQL permissions.

## Project layout

```
backend/          nhost.toml, migrations, metadata, functions, .secrets
frontend/
  src/
    views/        HomeView, SignInView, ProtectedView
    lib/nhost/    auth.ts (useAuth composable: Nhost client + session)
    lib/graphql.ts  typed GraphQL request helper
  schema.graphql  committed user-role GraphQL contract (codegen input)
  src/gql/        generated typed documents and types
AGENTS.md         project context for coding agents
CLAUDE.md         the same content, for Claude Code
SKILLS.md         repeatable workflows, for any coding agent
.mcp.json         optional Nhost MCP server configuration
.claude/skills/   the same workflows, in the layout Claude Code loads
```

## The typed data layer

`frontend/schema.graphql` is the committed contract for the `user` role and the
input to code generation. Operations are written with the generated `graphql()`
function and run through `gqlRequest`:

```sh
cd frontend
pnpm codegen        # dump schema from the running backend, then regenerate types
pnpm codegen:types  # regenerate types offline from the committed schema
```

Commit changes to both `schema.graphql` and `src/gql/` alongside the backend
change that altered the schema.

## Add a feature with an agent

This project ships agent context so a coding assistant can build on it unaided.
`AGENTS.md` / `CLAUDE.md` describe the stack and conventions. The repeatable
workflows ship twice with the same content: `SKILLS.md` in one file that any
agent can read, and `.claude/skills/` in the layout Claude Code loads on demand:

| Skill | What it does |
| --- | --- |
| `add-table` | Create a migration and track a new user-owned table |
| `add-permission` | Add role permissions with row-level ownership |
| `create-function` | Add a serverless function |
| `refresh-context` | Re-dump the schema and regenerate types after a change |

Once the backend is running, hand the project to an agent:

```sh
cd my-app
claude "Add a projects table that todos belong to, with per-user permissions,
and a page to manage them."
```

## Deploy

Connect the backend to [Nhost Cloud](https://app.nhost.io), then point the app at
your project by setting `VITE_NHOST_SUBDOMAIN` and `VITE_NHOST_REGION` in a
`.env` file to your cloud project's values, and deploy the built `dist/` to any
static host.
