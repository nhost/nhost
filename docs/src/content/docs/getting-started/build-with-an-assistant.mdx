You do not have to learn the Nhost CLI. Connect an assistant, describe what you want, and it runs the commands and writes the migration files. You review them and commit.

> Add a movies table with a title, director, and rating, and let signed-in users read it.

That works the same whether the backend runs on your machine or on Nhost Cloud. The [quickstarts](/getting-started/quickstart/react) each show the assistant path alongside the manual one.

## Three things to check yourself

The assistant does the work. These are the parts worth your own eyes.

**Read the migration.** Every schema change writes a file under `nhost/migrations/`. That file is what runs against every other environment, so reading it is the fastest way to catch a column type or a nullability choice you did not intend.

**Verify permissions.** They are the security boundary for your project: every GraphQL request runs under a role and is filtered by these rules, including the assistant's own. Describe the rule in chat, then open **Database → Permissions** in the dashboard and read back what was applied. See [Permissions](/products/graphql/permissions).

**Set secrets yourself.** Ask the assistant which variables a service needs, then enter the values through the dashboard so the real credential never passes through a chat transcript. See [secrets](/platform/cloud/secrets).

## Commit what it wrote

This is what makes the workflow durable rather than a pile of untracked changes. The assistant writes migrations under `nhost/migrations/`, metadata under `nhost/metadata/`, and configuration in `nhost.toml`. Commit them, and the project becomes reproducible: another developer runs `nhost up` and gets the same backend, and [deployments](/platform/cloud/deployments) apply the same migrations to Nhost Cloud.
