Now the fun part: the data. In this part you'll create the database schema,
lock it down with **owner-scoped permissions**, and add commands to create,
list, and organise notes — all over GraphQL.

:::note
This is **Part 3** of the [Notes CLI with Nhost and Rust](/getting-started/tutorials/rust/1-introduction)
series.

## Create the schema

Open the **SQL Editor** (**Database → SQL Editor** in the local Nhost dashboard
at `https://local.dashboard.local.nhost.run`) and
run the following. It creates two tables, `notes` and `tags`, plus a `note_tags`
join table and a trigger that keeps `updated_at` current.

```sql SQL Editor
CREATE OR REPLACE FUNCTION public.set_updated_at()
RETURNS TRIGGER AS $$
BEGIN NEW.updated_at = now(); RETURN NEW; END;
$$ LANGUAGE plpgsql;

CREATE TABLE public.notes (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id     uuid NOT NULL REFERENCES auth.users (id) ON DELETE CASCADE,
  title       text NOT NULL DEFAULT '',
  content     text NOT NULL DEFAULT '',
  is_pinned   boolean NOT NULL DEFAULT false,
  is_archived boolean NOT NULL DEFAULT false,
  created_at  timestamptz NOT NULL DEFAULT now(),
  updated_at  timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE public.tags (
  id      uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id uuid NOT NULL REFERENCES auth.users (id) ON DELETE CASCADE,
  name    text NOT NULL,
  color   text NOT NULL DEFAULT '#808080',
  UNIQUE (user_id, name)
);

CREATE TABLE public.note_tags (
  note_id uuid NOT NULL REFERENCES public.notes (id) ON DELETE CASCADE,
  tag_id  uuid NOT NULL REFERENCES public.tags (id) ON DELETE CASCADE,
  PRIMARY KEY (note_id, tag_id)
);

CREATE TRIGGER set_notes_updated_at BEFORE UPDATE ON public.notes
  FOR EACH ROW EXECUTE FUNCTION public.set_updated_at();
```

Make sure **Track this** is enabled for each table so it's exposed over GraphQL.
Then open each table's **Relationships** tab and track the foreign-key
relationships Nhost suggests. The Part 3 queries and permissions reference these
by name, so set them exactly: on `notes`, the array relationship to `note_tags`
as `noteTags` (Nhost suggests `note_tags`, so rename it); on `note_tags`, the object relationship to
`notes` as `note` and the one to `tags` as `tag`. A name mismatch surfaces later
as `"noteTags" does not exist` or `"note" does not exist`.

## Lock it down with permissions

By default a tracked table has no permissions — nobody can read or write it.
Open each table's **Edit Permissions** and grant the `user` role owner-scoped
access. The pattern is the same everywhere: a **column preset** sets `user_id`
from the session, and a **custom check** limits each action to the caller's own
rows. The GraphQL engine applies them to every request, using the user ID in
the caller's access token.

To add a custom check, choose **With custom check** under the action's row
permissions and build the rule. The checks below are written in Hasura's JSON
form: `{ "user_id": { "_eq": "X-Hasura-User-Id" } }` is the rule `user_id`
`_eq` `X-Hasura-User-Id`.

:::note
Track any relationship a permission references **before** you save that
permission. A custom check naming a relationship that isn't tracked yet fails
to save, and the dashboard shows a generic `Error: Unknown error occurred.`
instead of naming the missing relationship.
:::

- **tags** — for `insert`, check `name` and `color` and add a **column preset**
  `user_id = X-Hasura-User-Id`; leave `id` and `user_id` unchecked. For
  `select`, check those same columns **plus `id`** (a mutation that returns
  `{ id }` needs `id` in the select permission). For `update`, check `name` and
  `color` so edits take effect. Use the **custom check**
  `{ "user_id": { "_eq": "X-Hasura-User-Id" } }` for `select` / `update` /
  `delete`.
- **notes** — for `insert`, check `title`, `content`, `is_pinned`,
  `is_archived` and add the `user_id` column preset. For `select`,
  check those columns **plus `id` and `updated_at`** — the list query sorts by
  `updated_at`, and Hasura only lets you `order_by` columns the `select`
  permission exposes. For `update`, check the editable columns (`title`,
  `content`, `is_pinned`, `is_archived`). Use the **custom check**
  `{ "user_id": { "_eq": "X-Hasura-User-Id" } }` for `select` / `update` /
  `delete`.
- **note_tags** — gate it through the parent note. Check columns `note_id` and
  `tag_id` for **both** `insert` and `select` (there's no `user_id` preset — a
  `note_tags` row has no `user_id` column; ownership comes from the parent
  note). Use the custom check
  `{ "note": { "user_id": { "_eq": "X-Hasura-User-Id" } } }` for `insert`,
  `select` and `delete`.

## A GraphQL helper

Every command runs a query or mutation, so add a small helper. `query` builds
the operation, `variables` attaches JSON variables, and `send` decodes `data`
into whatever type you ask for — here a `serde_json::Value`, and it returns
`Error::GraphQl` if the response carries `errors`. A tiny `s` helper reads a
string field:

```rust title="src/main.rs"
use serde_json::{json, Value};

async fn gql(client: &Nhost, query: &str, vars: Value) -> Result<Value> {
    Ok(client.graphql.query(query).variables(vars).send().await?)
}

fn s(v: &Value, key: &str) -> String {
    v.get(key).and_then(Value::as_str).unwrap_or("").to_string()
}
```

## Create and list notes

`insert_notes_one` and the `notes` query are generated by Hasura from your
schema. Notice we never send `user_id` — the permission preset fills it in.

```rust title="src/main.rs"
async fn note_new(client: &Nhost, title: &str, content: Option<&str>) -> Result<()> {
    let obj = json!({ "title": title, "content": content.unwrap_or_default() });
    let data = gql(
        client,
        "mutation NewNote($obj: notes_insert_input!) { insert_notes_one(object: $obj) { id } }",
        json!({ "obj": obj }),
    )
    .await?;
    println!("created {}", s(&data["insert_notes_one"], "id"));
    Ok(())
}

async fn note_ls(client: &Nhost) -> Result<()> {
    let data = gql(
        client,
        "query {
            notes(order_by: [{is_pinned: desc}, {updated_at: desc}]) {
                id title is_pinned
            }
        }",
        Value::Null,
    )
    .await?;
    let notes = data["notes"].as_array().cloned().unwrap_or_default();
    if notes.is_empty() {
        println!("(no notes)");
        return Ok(());
    }
    for n in &notes {
        let pin = if n["is_pinned"].as_bool().unwrap_or(false) {
            "*"
        } else {
            " "
        };
        println!("{pin} {}  {}", s(n, "id"), s(n, "title"));
    }
    Ok(())
}
```

The `notes` query has no `where user_id` clause — it doesn't need one. The
custom check you configured means the GraphQL engine only ever returns the
caller's rows. It does still list **archived** notes, since the query doesn't filter
`is_archived` — so `archive` looks like it has no effect. Add
`where: {is_archived: {_eq: false}}` to the query to hide them.

## Update, tag, and organise

Updates go through `update_notes_by_pk`. One helper covers pin, archive, edit,
and move; a null primary-key result means the row doesn't exist *or* isn't yours:

```rust title="src/main.rs"
async fn note_set(client: &Nhost, id: &str, set: Value) -> Result<()> {
    let data = gql(
        client,
        "mutation UpdateNote($id: uuid!, $set: notes_set_input!) {
            update_notes_by_pk(pk_columns: {id: $id}, _set: $set) { id }
        }",
        json!({ "id": id, "set": set }),
    )
    .await?;
    if data["update_notes_by_pk"].is_null() {
        return Err("note not found or not permitted".into());
    }
    println!("updated {}", id);
    Ok(())
}
```

Tags use an **upsert**: `insert_tags_one` with `on_conflict` reuses an existing
tag (unique per `user_id, name`) instead of failing, then `insert_note_tags_one`
links it to the note:

```rust title="src/main.rs"
async fn upsert_tag(client: &Nhost, name: &str) -> Result<String> {
    let data = gql(
        client,
        "mutation UpsertTag($name: String!) {
            insert_tags_one(
                object: {name: $name}
                on_conflict: {constraint: tags_user_id_name_key, update_columns: [name]}
            ) { id }
        }",
        json!({ "name": name }),
    )
    .await?;
    let id = s(&data["insert_tags_one"], "id");
    if id.is_empty() {
        return Err("could not create tag".into());
    }
    Ok(id)
}

async fn note_tag(client: &Nhost, note_id: &str, tag_name: &str) -> Result<()> {
    let tag_id = upsert_tag(client, tag_name).await?;
    gql(
        client,
        "mutation TagNote($noteId: uuid!, $tagId: uuid!) {
            insert_note_tags_one(
                object: {note_id: $noteId, tag_id: $tagId}
                on_conflict: {constraint: note_tags_pkey, update_columns: []}
            ) { note_id }
        }",
        json!({ "noteId": note_id, "tagId": tag_id }),
    )
    .await?;
    println!("tagged {} with #{}", note_id, tag_name);
    Ok(())
}
```

Now expose these as commands. We keep the UX flat — `new`, `ls`,
`pin`, `archive`, `tag` — so each is just another variant on the
`Command` enum (the full CLI's `show`, its `tag ls`/`new`/`add`/`rm` group and
its `--content` flag follow the same pattern):

```rust title="src/main.rs"
    /// Create a note
    New {
        title: String,
        content: Option<String>,
    },
    /// List your notes
    Ls,
    /// Pin a note
    Pin { id: String },
    /// Archive a note
    Archive { id: String },
    /// Tag a note (creates the tag if needed)
    Tag { note_id: String, tag_name: String },
```

Then add the matching arms in `run` — `pin` and `archive` share the
`note_set` helper:

```rust title="src/main.rs"
        Command::New { title, content } => note_new(&client, &title, content.as_deref()).await,
        Command::Ls => note_ls(&client).await,
        Command::Pin { id } => note_set(&client, &id, json!({ "is_pinned": true })).await,
        Command::Archive { id } => note_set(&client, &id, json!({ "is_archived": true })).await,
        Command::Tag { note_id, tag_name } => note_tag(&client, &note_id, &tag_name).await,
```

## The complete `src/main.rs`

Here's the whole `src/main.rs` after Part 3. Collapsed sections are unchanged from
earlier parts; highlighted lines are what this part added. Press **Copy** to grab
the entire file.

```rust title="src/main.rs" collapse={1-7,9-29,43-66,72-168} {8-8,30-42,67-71,169-267}
use std::io::{self, IsTerminal};
use std::path::PathBuf;

use clap::{Parser, Subcommand};
use nhost::auth::{SignInEmailPasswordRequest, SignOutRequest, SignUpEmailPasswordRequest};
use nhost::session::FileStore;
use nhost::Nhost;
use serde_json::{json, Value};

type Result<T> = std::result::Result<T, Box<dyn std::error::Error>>;

/// A note-taking CLI built on Nhost.
#[derive(Parser)]
#[command(name = "notes-cli", version, about)]
struct Cli {
    #[command(subcommand)]
    command: Command,
}

#[derive(Subcommand)]
enum Command {
    /// Create an account (and sign in if email verification is off)
    Signup { email: String },
    /// Sign in with email and a securely supplied password
    Login { email: String },
    /// Sign out and clear the saved session
    Logout,
    /// Show the currently signed-in user
    Whoami,
    /// Create a note
    New {
        title: String,
        content: Option<String>,
    },
    /// List your notes
    Ls,
    /// Pin a note
    Pin { id: String },
    /// Archive a note
    Archive { id: String },
    /// Tag a note (creates the tag if needed)
    Tag { note_id: String, tag_name: String },
}

#[tokio::main]
async fn main() {
    let cli = Cli::parse();
    if let Err(e) = run(cli.command).await {
        eprintln!("error: {e}");
        std::process::exit(1);
    }
}

async fn run(command: Command) -> Result<()> {
    let client = make_client()?;
    match command {
        Command::Signup { email } => {
            let password = read_password()?;
            signup(&client, &email, &password).await
        }
        Command::Login { email } => {
            let password = read_password()?;
            login(&client, &email, &password).await
        }
        Command::Logout => logout(&client).await,
        Command::Whoami => whoami(&client).await,
        Command::New { title, content } => note_new(&client, &title, content.as_deref()).await,
        Command::Ls => note_ls(&client).await,
        Command::Pin { id } => note_set(&client, &id, json!({ "is_pinned": true })).await,
        Command::Archive { id } => note_set(&client, &id, json!({ "is_archived": true })).await,
        Command::Tag { note_id, tag_name } => note_tag(&client, &note_id, &tag_name).await,
    }
}

fn make_client() -> Result<Nhost> {
    let path = session_path();
    if let Some(parent) = path.parent() {
        std::fs::create_dir_all(parent)?;
    }
    Ok(Nhost::builder()
        .subdomain(env("NHOST_SUBDOMAIN", "local"))
        .region(env("NHOST_REGION", "local"))
        .session_store(FileStore::new(path))
        .build()?)
}

fn session_path() -> PathBuf {
    if let Ok(p) = std::env::var("NHOST_NOTES_SESSION") {
        return PathBuf::from(p);
    }
    let base = std::env::var("XDG_CONFIG_HOME")
        .map(PathBuf::from)
        .unwrap_or_else(|_| {
            PathBuf::from(std::env::var("HOME").unwrap_or_default()).join(".config")
        });
    base.join("nhost-notes").join("session.json")
}

fn env(key: &str, fallback: &str) -> String {
    std::env::var(key).unwrap_or_else(|_| fallback.to_string())
}

fn read_password() -> Result<String> {
    if let Ok(password) = std::env::var("NOTES_PASSWORD") {
        return Ok(password);
    }
    if !io::stdin().is_terminal() {
        return Err("stdin is not a terminal; set NOTES_PASSWORD for non-interactive use".into());
    }
    Ok(rpassword::prompt_password("Password: ")?)
}

async fn signup(client: &Nhost, email: &str, password: &str) -> Result<()> {
    let response = client
        .auth
        .sign_up_email_password(SignUpEmailPasswordRequest {
            email: email.to_string(),
            password: password.to_string(),
            options: None,
            code_challenge: None,
        })
        .await?;
    // Sign-up returns no session while the email is unverified, so check the
    // response rather than whatever session is already stored.
    if response.body.session.is_some() {
        println!("signed up and logged in as {email}");
    } else {
        println!("signed up; verify your email, then `login`");
    }
    Ok(())
}

async fn login(client: &Nhost, email: &str, password: &str) -> Result<()> {
    client
        .auth
        .sign_in_email_password(SignInEmailPasswordRequest {
            email: email.to_string(),
            password: password.to_string(),
        })
        .await?;
    println!("logged in as {email}");
    Ok(())
}

async fn logout(client: &Nhost) -> Result<()> {
    if let Some(sess) = client.session().await? {
        let _ = client
            .auth
            .sign_out(SignOutRequest {
                refresh_token: Some(sess.session.refresh_token),
                all: None,
            })
            .await;
    }
    client.clear_session().await?;
    println!("logged out");
    Ok(())
}

async fn whoami(client: &Nhost) -> Result<()> {
    match client.session().await?.and_then(|s| s.session.user) {
        Some(u) => {
            println!("{} ({})", u.email.unwrap_or_default(), u.id);
            Ok(())
        }
        None => Err("not logged in".into()),
    }
}

    Ok(client.graphql.query(query).variables(vars).send().await?)
}
```

## Try it

```bash Terminal
cargo run -- new "Shopping" "buy milk"
cargo run -- ls
#   7f3a...  Shopping

cargo run -- tag 7f3a... urgent
```

Sign in as a *different* user and you'll see an empty list — the permissions
guarantee isolation without a single line of filtering in your code.
