Welcome to the **Notes CLI with Nhost and Python** series! Over five parts you'll
build a real command-line notes manager on top of the async Nhost Python SDK that
exercises every core Nhost product: authentication, the GraphQL database,
file storage, and serverless functions.

## About This Tutorial Series

This series is divided into **5 parts**, each focusing on one Nhost product. By
the end you'll have a `notes` CLI that can:

- **Authenticate** — sign up, sign in, and stay signed in across runs with a
  persisted session (`login` / `logout` / `whoami`)
- **Manage notes** — create, list, edit, tag, and organise notes into notebooks
  over GraphQL, with per-user permissions enforced by the database
- **Attach files** — upload attachments to Nhost Storage and download them again
- **Export & share** — call a serverless function to export notes and share a
  note with another user

:::note
This is **Part 1** in the series. This part spins up a local Nhost backend and
scaffolds the CLI so later parts can focus on one product at a time.
:::

## Prerequisites

- **Python 3.11+** installed on your machine
- Basic knowledge of Python and `asyncio`
- [Docker](https://docs.docker.com/get-docker/) — the local Nhost stack runs in containers
- The **Nhost CLI**

## Set Up the Local Backend

You'll run the entire Nhost stack — PostgreSQL, GraphQL, Auth, Storage, and
Functions — locally with the Nhost CLI. No account or cloud project is required.

### Install the Nhost CLI

```bash Terminal
curl -sSL https://raw.githubusercontent.com/nhost/nhost/main/cli/get.sh | bash
```

Other install methods (npm, Homebrew, Nix) are covered in the
[CLI Quickstart](/getting-started/local-development/cli).

### Initialize and start the project

Create a project directory, scaffold the backend configuration, and start the
stack:

```bash Terminal
mkdir notes-cli
cd notes-cli

nhost init   # scaffolds nhost/ (config, migrations, metadata) and functions/
nhost up     # starts the local backend with Docker
```

`nhost up` prints the URLs for your local services. The one you'll use most is
the **Dashboard** at `https://local.dashboard.local.nhost.run`, where you'll
configure auth, permissions, and storage in later parts. Leave `nhost up`
running in its own terminal.

:::note
`nhost login` is only needed if you later want to pull config from — or deploy
to — an Nhost Cloud project. Everything in this tutorial stays local, so you can
skip it.
:::

## Scaffold the CLI

In the same project directory, create a virtual environment and install the SDK
alongside your backend configuration (Python 3.11+):

```bash Terminal
python -m venv .venv && source .venv/bin/activate

# nhost is not on PyPI yet, so depend on the repository revision for now. Once
# published, use: pip install nhost typer
pip install "nhost @ git+https://github.com/nhost/nhost.git@c2a676ab7eb6c28082dd1412cd49055073c70635#subdirectory=packages/nhost-python" typer
```

[Typer](https://typer.tiangolo.com/) parses the command line and generates
`--help` for us. Now create a minimal `main.py`. The Nhost client is async, but
Typer commands are plain sync functions, so each command wraps its work in
`asyncio.run`. It creates the client — pointed at your local backend by default —
and dispatches to a command. We start with a single `whoami` command and add the
rest one product at a time in the following parts.

```python title="main.py"
import asyncio
import os

import typer

from nhost import NhostClientOptions, create_client

app = typer.Typer(
    name="notes-cli",
    help="Nhost notes CLI",
    add_completion=False,
    no_args_is_help=True,
)


@app.callback()
def cli() -> None:
    """Nhost notes CLI."""
    # Keeps Typer in multi-command mode while we only have one command; from
    # Part 2 on there are several and this callback becomes optional.


def make_client():
    # The client middleware attaches the access token to every request and
    # refreshes it automatically once we sign in.
    return create_client(
        NhostClientOptions(
            subdomain=os.environ.get("NHOST_SUBDOMAIN", "local"),
            region=os.environ.get("NHOST_REGION", "local"),
        )
    )


def run(coro) -> None:
    # Each command is an async coroutine that takes the client; open it, run the
    # command, and let asyncio drive it to completion.
    async def runner() -> None:
        async with make_client() as nhost:
            await coro(nhost)

    asyncio.run(runner())


async def cmd_whoami(nhost) -> None:
    session = nhost.get_user_session()
    if session is None or session.user is None:
        raise SystemExit("not logged in")
    print(f"{session.user.email} ({session.user.id})")


@app.command("whoami")
def whoami() -> None:
    """Show the currently signed-in user."""
    run(cmd_whoami)


def main() -> None:
    app()


if __name__ == "__main__":
    main()
```

With the local backend running, the client defaults to it automatically — no
environment variables needed. Run:

```bash Terminal
python main.py --help      # Typer prints the command list
python main.py whoami      # "not logged in" until Part 2
```

`--help` lists the commands (just `whoami` so far); `whoami` reports that you're
not signed in yet. The client is wired up and ready.

:::tip
Want to point the CLI at an Nhost Cloud project instead? Set `NHOST_SUBDOMAIN`
and `NHOST_REGION` to your cloud project's values and the same code connects
there. This tutorial stays local throughout.
:::
