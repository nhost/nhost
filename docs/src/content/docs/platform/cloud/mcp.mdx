Nhost runs a hosted MCP server for the Nhost Cloud platform at <CopyText text="https://mcp.nhost.io" />. Add it as a remote connector in any MCP client that supports one and an AI assistant can answer questions about your organizations, projects, and deployments.

There is nothing to install, no config file, and no token to copy. You sign in with your Nhost account over OAuth2 and your client keeps the session.

<Prompt>
Which of my projects had a failed deployment in the last week?
</Prompt>

## Connect

<Steps>

1. In your client, add a custom connector or remote MCP server with the URL `https://mcp.nhost.io`.
2. Your client sends you to the Nhost consent page, showing the scopes it's asking for — typically `openid`, `graphql:role:user_mcp`, and `offline_access`.
3. Approve the request. The client completes the OAuth2 flow and the tools become available.

</Steps>

Per-client instructions:

- **Claude** — **Settings → Connectors** (or **Customize → Connectors** in some versions), then **+ Add custom connector**.
- **Cursor** — add it under Cursor Settings → MCP:

  ```json
  {
    "mcpServers": {
      "nhost-cloud": {
        "url": "https://mcp.nhost.io"
      }
    }
  }
  ```

- **Any other client** that supports remote MCP servers with OAuth2 — add an HTTP/remote server with the same URL and complete the authorization when prompted.

:::note
Clients that only support local (stdio) servers can't connect to this one. Use the [CLI MCP server](/platform/cli/mcp/cloud-setup) instead — it runs locally and reaches the same platform data.
:::

## What it can do

The connector exposes the three [Backend MCP](/products/ai/mcp) tools — `get-schema`, `graphql-query`, and `graphql-mutation` — over the Nhost Cloud platform's own GraphQL API. An assistant typically calls `get-schema` first to learn the data model, then queries it.

It's useful for questions you'd otherwise answer by clicking through the dashboard:

- which projects exist, in which organizations and regions
- the deployment history of a project, and which deployments failed
- how a project is configured, and how two projects differ

**Access is read-only.** Requests run under the `user_mcp` role, which grants no mutation permissions, so `graphql-mutation` is rejected even though the tool is listed. Everything is scoped to your own account: the assistant sees exactly what you would see signed in to the dashboard, and nothing belonging to anyone else.

## What it can't do

This connector covers the platform, not your project's own contents. It cannot:

- read or write the data in your project's database
- change project configuration, environment variables, or secrets
- create migrations, edit permission rules, or change your schema

For any of those, use the [CLI MCP server](/platform/cli/mcp/cloud-setup), which authenticates as you and can write when you configure it to.

The `user_mcp` role's permissions will widen over time as this connector develops, so what it can answer today is a floor, not a ceiling.

## How it's built

The connector is an instance of the open-source [Backend MCP](/products/ai/mcp) service, deployed on Nhost Run against the Nhost Cloud platform's own backend, with `MCP_ENFORCE_ROLE=user_mcp`. It's the same service you can deploy in front of your own project to give **your** users an AI interface — see [Deployment](/products/ai/mcp/deployment).
