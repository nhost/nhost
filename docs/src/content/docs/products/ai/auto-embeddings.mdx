Auto-embeddings use [pgvector](https://github.com/pgvector/pgvector) and OpenAI embedding models to
keep a vector column synchronized with selected row data. The service also creates PostgreSQL
functions for natural-language search and row-to-row similarity search, then tracks those functions
in your GraphQL API.

:::note[Graphite users]
This page documents the current Nhost AI service and the `ai` schema. For an existing Graphite
project, use the [deprecated Graphite guide](/products/graphite/auto-embeddings) until you migrate
its `graphite` configuration and function names.
:::

Configure the [core AI service environment](/products/ai#deploy-the-current-service) first.
`OPENAI_API_KEY` is required for synchronization and natural-language search; `OPENAI_ORG` is
optional. The search function also depends on a reachable `AI_BASE_URL` and a shared
`AI_WEBHOOK_SECRET`.

## How synchronization works

At each synchronization interval, the service:

1. Loads rows from `ai.auto_embeddings_configuration` whose `query` and `mutation` are set.
2. Runs each configuration's GraphQL `query` through the project's internal GraphQL connection.
3. Requires every returned object to contain an `id` field.
4. Serializes the returned object and asks OpenAI for an embedding using the configured `model`.
5. Runs the configuration's GraphQL `mutation` with `id` and `embeddings` variables.

The standalone service uses a one-minute interval by default. Set `SYNCH_PERIOD`, such as `5m`, to
change it for a self-hosted deployment.

A target table must have exactly one primary-key column. The vector column's dimensions must match
the output of the selected embedding model. The service supports OpenAI embedding model identifiers,
including `text-embedding-ada-002`, `text-embedding-3-small`, and `text-embedding-3-large`.

## Example: movie embeddings

This example embeds `name`, `genre`, and `overview` from a `movies` table by using
`text-embedding-3-small`.

### Create the vector and status columns

`text-embedding-3-small` produces 1,536-dimensional vectors by default:

```sql
CREATE EXTENSION IF NOT EXISTS vector;

ALTER TABLE public.movies
  ADD COLUMN embeddings vector(1536),
  ADD COLUMN embeddings_outdated boolean NOT NULL DEFAULT true;
```

Add a trigger that marks the vector as outdated when source content changes and current when the
embedding mutation writes a new vector:

```sql
CREATE OR REPLACE FUNCTION public.set_movies_embeddings_outdated()
RETURNS trigger AS $$
BEGIN
  IF NEW.name IS DISTINCT FROM OLD.name
    OR NEW.genre IS DISTINCT FROM OLD.genre
    OR NEW.overview IS DISTINCT FROM OLD.overview THEN
    NEW.embeddings_outdated := true;
  ELSIF NEW.embeddings IS DISTINCT FROM OLD.embeddings THEN
    NEW.embeddings_outdated := false;
  END IF;

  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER set_movies_embeddings_outdated
BEFORE UPDATE ON public.movies
FOR EACH ROW
EXECUTE FUNCTION public.set_movies_embeddings_outdated();
```

You can use another change-detection strategy. The only service requirement is that the GraphQL
query returns the rows that currently need an embedding.

### Define the source query

Return `id` plus every value that should contribute to the embedding:

```graphql
query GetMoviesWithoutCurrentEmbeddings {
  movies(
    where: {
      _or: [
        { embeddings: { _is_null: true } }
        { embeddingsOutdated: { _eq: true } }
      ]
    }
    limit: 20
  ) {
    id
    name
    genre
    overview
  }
}
```

Keep batches bounded. The query runs again at the next synchronization interval until no matching
rows remain.

### Define the update mutation

The service supplies variables named `id` and `embeddings`:

```graphql
mutation UpdateMovieEmbedding($id: uuid!, $embeddings: vector) {
  updateMovie(
    pk_columns: { id: $id }
    _set: { embeddings: $embeddings }
  ) {
    id
  }
}
```

### Insert the configuration

:::caution[Trusted administrators only]
The current service interpolates `name`, `schemaName`, `tableName`, `columnName`, and the detected
primary-key column into administrative SQL without quoting or validating them. Never allow
untrusted application roles to insert, update, or delete these configurations. Use lowercase SQL
identifiers matching `^[a-z_][a-z0-9_]*$`; keep identifiers within PostgreSQL's 63-byte limit and
`name` within 52 bytes so generated function names are not truncated. The `model` is also embedded
in generated SQL, so allow only known OpenAI model identifiers. Enforce these checks in your
deployment until the service validates and quotes configuration values itself.
:::

Run this operation only as a trusted administrator or deployment process:

```graphql
mutation ConfigureMovieEmbeddings {
  insertAiAutoEmbeddingsConfiguration(
    object: {
      name: "movies"
      model: "text-embedding-3-small"
      schemaName: "public"
      tableName: "movies"
      columnName: "embeddings"
      query: "query GetMoviesWithoutCurrentEmbeddings { movies(where: { _or: [{ embeddings: { _is_null: true } }, { embeddingsOutdated: { _eq: true } }] }, limit: 20) { id name genre overview } }"
      mutation: "mutation UpdateMovieEmbedding($id: uuid!, $embeddings: vector) { updateMovie(pk_columns: { id: $id }, _set: { embeddings: $embeddings }) { id } }"
    }
  ) {
    id
    name
  }
}
```

The `name` must be unique. The combination of `schemaName`, `tableName`, and `columnName` must also
be unique.

Creating or updating the configuration triggers the AI service to create and track two database
functions:

- `ai_search_movies(query, amount, maxdistance)` embeds a text query and orders rows by cosine
  distance.
- `ai_similar_movies(id, amount, maxdistance)` compares rows with the vector stored on one source
  row and excludes that source row from the result. The first argument uses the target table's
  actual primary-key column name; this example uses `id`.

The service exposes these functions with the custom GraphQL roots `aiSearchMovies`,
`aiSearchMoviesAggregate`, `aiSimilarMovies`, and `aiSimilarMoviesAggregate`.

## Query generated functions

Natural-language search:

```graphql
query SearchMovies($query: String!) {
  aiSearchMovies(
    args: { query: $query, amount: 5, maxdistance: 0.6 }
  ) {
    id
    name
    overview
  }
}
```

Similarity search:

```graphql
query SimilarMovies($id: uuid!) {
  aiSimilarMovies(
    args: { id: $id, amount: 5, maxdistance: 0.6 }
  ) {
    id
    name
    overview
  }
}
```

`maxdistance` defaults to `1.0`. Lower values require closer cosine similarity; `0.0` is an exact
vector match. The lowercase spelling reflects PostgreSQL's handling of the unquoted function
argument name.

Because each function returns the target table's row type and is tracked in the GraphQL API, normal
select permissions on that table apply to its results. Configure function permissions and table
row filters for every role that should use these fields.

## Update or remove a configuration

The generated GraphQL roots also include:

- `aiAutoEmbeddingsConfigurations` and `aiAutoEmbeddingsConfiguration`
- `updateAiAutoEmbeddingsConfiguration`
- `deleteAiAutoEmbeddingsConfiguration`

:::caution[Renames and cleanup]
Updating `name`, `schemaName`, `tableName`, or `columnName` deploys functions for the new values but
does not remove functions created from the previous values. Clean up those tracked functions
manually before changing identifiers.

On deletion, the service untracks the current functions and attempts to drop them. Verify physical
cleanup, especially outside schemas on the database search path, because the current drop statement
is not schema-qualified. The underlying vector column and stored embeddings always remain in your
table.
:::
