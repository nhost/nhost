Nhost AI adds automatic vector embeddings and multi-provider agents to your Nhost project.
The current service lives in [`services/ai`](https://github.com/nhost/nhost/tree/main/services/ai)
and uses your project's PostgreSQL database and GraphQL API.

:::note[Coming from Graphite?]
[Graphite](/products/graphite) is deprecated and has been superseded by Nhost AI.
Graphite Assistants and the current Agents API are not API-compatible. The legacy documentation
remains available for maintaining existing Graphite deployments.
:::

## Features

### Agents

Build conversational agents that:

- Use Anthropic, OpenAI, or Google Gemini models
- Stream provider-generated text chunks with Server-Sent Events (SSE)
- Persist agents, sessions, and messages in the `ai` PostgreSQL schema
- Use built-in web search, web fetch, and GraphQL tools
- Discover tools from remote MCP servers
- Pause selected tool calls for human approval
- Chain tool calls for up to 25 iterations per request

Agent definitions and sessions are managed through your auto-generated GraphQL API. Messages are
sent through REST endpoints that authorize session access with your GraphQL permission rules.

### Auto-embeddings

Keep vector columns synchronized with source data using OpenAI embedding models. Each configuration
defines a GraphQL query for rows that need embeddings and a mutation for writing the generated
vectors. The service also deploys and tracks PostgreSQL functions for natural-language and
similarity search.

The generated GraphQL function fields use your existing table permissions, so query results remain
scoped to the caller's role.

## Deploy the current service

Run the current `nhost/ai` image as a separate service. The `[ai]` section in the current
[`nhost.toml` reference](/reference/configuration#ai) configures deprecated Graphite releases and
does not configure this runtime.

The service connects to PostgreSQL and the GraphQL API at startup, applies its database migrations,
and tracks its metadata before serving requests. Your PostgreSQL build must make the `vector`,
`http`, and `pg_jsonschema` extensions available, and the database must contain `auth.users`. The
`POSTGRES_CONNECTION` role must be able to create the `ai` schema and run `SET ROLE postgres` for
extension installation—typically `postgres` or an appropriately privileged member.

Configure these core environment variables:

| Variable | Purpose |
| --- | --- |
| `POSTGRES_CONNECTION` | PostgreSQL connection used for migrations, persistence, and session locks |
| `NHOST_GRAPHQL_URL` | Project GraphQL endpoint |
| `HASURA_GRAPHQL_ADMIN_SECRET` | Administrative GraphQL access for migrations and internal operations |
| `AI_BASE_URL` | Internal service origin reachable by the GraphQL engine and PostgreSQL, such as `http://ai:8090` |
| `AI_WEBHOOK_SECRET` | Secret shared with the GraphQL engine for AI webhook calls |

Make `AI_WEBHOOK_SECRET` available to both the AI service and GraphQL engine. Add provider variables
from the [Agents guide](/products/ai/agents#providers) and `OPENAI_API_KEY` when using
auto-embeddings.

The binary listens on port `8090` by default. Expose it through your own ingress or reverse proxy.
In the examples, `<AI_SERVICE_URL>` means that public origin without `/v1`, such as
`https://ai.example.com`. The development
[Docker Compose file](https://github.com/nhost/nhost/blob/main/services/ai/build/dev/docker/docker-compose.yaml)
is the authoritative self-hosting reference.

## APIs

Nhost AI does not add a service-owned GraphQL schema. Instead, it:

- Tracks tables in the `ai` schema through your GraphQL API
- Exposes agent and auto-embedding configuration through generated GraphQL fields
- Tracks generated search functions in the GraphQL API
- Provides REST endpoints for streaming agent messages and approving tool calls
