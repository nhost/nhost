Deploy the Backend MCP Server alongside your project on [Nhost Run](/products/run). It can reach your project's GraphQL and Storage APIs over the internal network.

## Before you deploy

Backend MCP relies on your Nhost Auth project being set up as an OAuth2 provider. Complete the [authentication prerequisites](/products/ai/mcp/authentication#prerequisites) — the OAuth2 provider, CIMD, and a consent page — before you deploy.

Set `MCP_AUTH_URL` to your project's Auth URL, for example `https://SUBDOMAIN.auth.REGION.nhost.run/v1`. Set `MCP_REALM` to the [public URL](/products/run/networking#exposing-your-service-to-the-internet) of your MCP service and replace the sample `MCP_INSTRUCTIONS` with a description of your application.

The installer uses the project's internal GraphQL and Storage endpoints. Set `MCP_ENFORCE_ROLE` to your [dedicated MCP role](/products/ai/mcp/permissions#enforce-a-dedicated-role), or remove it to use each signed-in user's default role. If the assistant doesn't need [file downloads](#file-downloads), remove `MCP_STORAGE_URL`.

</TabItem>
<TabItem label="run-mcp.toml">

Add a `run-mcp.toml` file to your project directory:

```toml
name = 'mcp'
command = ['mcp']

[image]
image = 'nhost/mcp:0.4.0'

[[environment]]
name = 'MCP_AUTH_URL'
value = 'https://SUBDOMAIN.auth.REGION.nhost.run/v1'

[[environment]]
name = 'MCP_REALM'
value = 'https://mcp.acme.com'

[[environment]]
name = 'MCP_GRAPHQL_ENDPOINT'
value = 'http://hasura-service:8080/v1/graphql'

[[environment]]
name = 'MCP_STORAGE_URL'
value = 'http://hasura-storage-service:5000/v1'

[[environment]]
name = 'MCP_STORAGE_MAX_TRANSFER_BYTES'
value = '10000000'

[[environment]]
name = 'MCP_INSTRUCTIONS'
value = 'This MCP server interacts with my application'

[[environment]]
name = 'MCP_ENFORCE_ROLE'
value = 'user_mcp'

[[ports]]
port = 3000
type = 'http'
publish = true

[resources]
replicas = 1

[resources.compute]
cpu = 125
memory = 256
```

Replace the sample Auth URL, realm, instructions, and role with values for your project. Set `SERVICE_ID` to your Nhost Run service ID, then deploy Backend MCP:

```bash
nhost run config-deploy \
  --config run-mcp.toml \
  --service-id $SERVICE_ID
```

Once the service is running, [connect your MCP client](/products/ai/mcp/clients) using the service's public URL.

## File downloads

The installer and TOML example enable file downloads with `MCP_STORAGE_URL=http://hasura-storage-service:5000/v1`. The tool only downloads files the user's role can read. To give the assistant file access, grant [Download permission](/products/ai/mcp/permissions#storage-permissions) for the intended files and buckets. Remove `MCP_STORAGE_URL` to turn off the tool.

The examples set a 10 MB per-download limit for the 256 MiB service. This does not limit the number of simultaneous downloads. See [Transfer limits](/products/ai/mcp/configuration#transfer-limits) before raising the limit or serving multiple downloads at once.

If you deploy outside the [Nhost Run internal network](/products/run/networking), set `MCP_STORAGE_URL` to your project's reachable Storage URL, including `/v1`.

## Run locally

To run Backend MCP in your local Nhost stack, set `MCP_AUTH_URL` in `run-mcp.toml` to your local Auth URL, for example `https://local.auth.local.nhost.run/v1`. Keep the internal GraphQL and Storage URLs. Then start the stack:

```bash
nhost up --run-service run-mcp.toml
```

If you run the MCP process directly on your host instead, use the local URLs shown by the CLI, such as `https://local.graphql.local.nhost.run/v1/graphql` and `https://local.storage.local.nhost.run/v1`.

## Configuration reference

Every setting can be supplied as a flag or an environment variable. `MCP_GRAPHQL_ENDPOINT` and `MCP_AUTH_URL` are required. See [Configuration](/products/ai/mcp/configuration) for the full list.
