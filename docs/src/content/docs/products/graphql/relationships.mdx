A relationship is a field on a table's GraphQL type that returns the related rows of another table. An object relationship returns one row, and an array relationship returns a list. Relationships are stored in your project's metadata, so adding one doesn't change your tables.

:::caution[Requirements]
- A project on Nhost Cloud or a local project run with `nhost up`.
- The tables you want to relate, tracked in your GraphQL API.
- To relate a table to a remote schema or another database: a [remote schema](/products/graphql/remote-schemas) added to the project, or a second database connected to it.
:::

## Example tables

The steps on this page use two tables based on the <a href="https://github.com/nhost/nhost/tree/main/examples/demos/backend" target="_blank" rel="noopener noreferrer">backend demo</a>. `communities` holds the communities, and `community_members` records which users belong to each one through its `community_id` column. The SQL leaves out the foreign key on `community_id`, which you add in [Create relationships with a foreign key](#create-relationships-with-a-foreign-key):

```sql
CREATE TABLE public.communities (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name TEXT NOT NULL UNIQUE,
    description TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE public.community_members (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
    community_id UUID NOT NULL,
    joined_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE(user_id, community_id)
);
```

The examples relate these tables in both directions. An object relationship `community` on `community_members` returns a member's community, and an array relationship `community_members` on `communities` returns a community's members.

To follow along, run the SQL in <a href="https://app.nhost.io/orgs/_/projects/_/database/console/default" target="_blank" rel="noopener noreferrer"><strong>Database → SQL Console</strong><span class="not-content" style="display:inline-block;vertical-align:-0.2em;margin-left:.1em"><Icon name="external" /></span></a> with **Track this** on. That tracks the tables but adds no relationships, which is the starting point the next sections assume.

If you create the tables in the table form instead, with the foreign key on `user_id`, the dashboard adds the `user` relationship and its reverse on `auth.users` right away, and [Add a suggested relationship](#add-a-suggested-relationship) has nothing left to suggest. You can also apply the same steps to your own tables.

## Open a table's relationships

Open <a href="https://app.nhost.io/orgs/_/projects/_/database/browser/default" target="_blank" rel="noopener noreferrer"><strong>Database → Table editor & Browser</strong><span class="not-content" style="display:inline-block;vertical-align:-0.2em;margin-left:.1em"><Icon name="external" /></span></a>, open the **⋯** menu next to `communities`, and select **Edit Relationships**.

![The communities table menu in the Table editor with Edit Relationships highlighted](/images/products/graphql/relationships/table-edit-relationships-nav.png)

The drawer that opens has two lists. **Relationships** shows each relationship's name, source, and type, and under **Relationship**, the columns it joins. **Suggested Relationships** shows the ones the dashboard can create from foreign keys. For `communities`, both lists are empty for now. The next section adds a foreign key, and with it the first relationship.

![The Edit Relationships drawer for public.communities with both lists empty](/images/products/graphql/relationships/table-edit-relationships.png)

A relationship name becomes a field name on the table's GraphQL type, so every dialog on this page requires it to start with a letter or an underscore and contain only letters, numbers, and underscores.

## Create relationships with a foreign key

When you add a foreign key in the table form, the dashboard also creates a relationship on each of the two tables. To add the foreign key on `community_members.community_id`:

<Steps>

1. Open the **⋯** menu next to `community_members` and select **Edit Table**. ![The community_members table menu with Edit Table highlighted](/images/products/graphql/relationships/table-edit-table.png)

2. Under **Foreign Keys**, click **Add Foreign Key**. ![The Foreign Keys section of the Edit Table form with the Add Foreign Key button](/images/products/graphql/relationships/table-foreign-keys.png)

3. In the **Add a Foreign Key Relation** dialog, set:

   - **Schema**: `public`
   - **Table**: `communities`
   - **Referenced key**: the primary key on `id`
   - **Column**: `community_id`, in the row that references `id`

   Then click **Add**. ![The Add a Foreign Key Relation dialog with community_id referencing communities.id](/images/products/graphql/relationships/table-add-foreign-key.png)

4. Click **Save**.

</Steps>

The dashboard then creates two relationships:

| Table | Relationship | Type | Named after |
| --- | --- | --- | --- |
| `community_members` | `community` | Object | the referenced table, `communities`, in the singular |
| `communities` | `community_members` | Array | the table with the foreign key, `community_members`, in the plural |

The names or the result differ in these cases:

- If the foreign key's columns cover a primary key or unique constraint on `community_members`, for example if `community_id` alone were unique, each community can have at most one member row. The relationship on `communities` is then an object relationship named in the singular, `community_member`.
- If another foreign key on `community_members` already has a relationship with the same name, or you add two foreign keys in one save that produce the same name on the same table (two columns that both reference `auth.users`, for example), the dashboard adds the foreign key's column names to the name, as in `community_community_id`.
- If any other relationship already has the name, the dashboard saves the foreign key, shows an error, and creates neither relationship. Rename or delete the existing relationship, then add each one from its own table's [Suggested Relationships](#add-a-suggested-relationship).

## Add a suggested relationship

A foreign key created in SQL, through the **SQL Console** or a migration, comes with no relationships. **Suggested Relationships** lists the ones that are missing. In each table's drawer, it shows the relationships that start from that table, through a foreign key on the table or one that points at it.

The example SQL creates the foreign key from `community_members.user_id` to `auth.users`, so the `community_members` drawer suggests an object relationship named `user`:

<Steps>

1. Open the **⋯** menu next to `community_members`, select **Edit Relationships**, and click **Add** on the `user` row. ![Suggested Relationships for community_members with the user row and its Add button](/images/products/graphql/relationships/table-add-suggested-relationship.png)

2. The **Add Suggested Relationship** dialog shows the type, **Object Relationship**, and the join, `public.community_members / user_id → auth.users / id`. The **Relationship Name** is already `user`. Keep it or change it. ![The Add Suggested Relationship dialog with the name user](/images/products/graphql/relationships/table-create-relationship.png)

3. Click **Create Relationship**.

</Steps>

The suggestion leaves the list and appears under **Relationships**, and `community_members.user` now returns a member's user.

## Create a relationship by column mapping

**Relationship +** joins a table on any pair of columns you choose. A view has no foreign keys, so this is how you relate one. The example relates `communities` to this view:

```sql
CREATE VIEW public.community_member_counts AS
SELECT community_id, count(*) AS member_count
FROM public.community_members
GROUP BY community_id;
```

Run it in the **SQL Console** with **Track this** on, as you did for the tables. The **Create Relationship** dialog lists only tracked tables and views.

<Steps>

1. Open the **⋯** menu next to `communities`, select **Edit Relationships**, and click **Relationship +**. ![The Edit Relationships drawer for communities with the Relationship + button highlighted](/images/products/graphql/relationships/table-add-relationship.png)

2. Fill in the **Create Relationship** dialog:

   - **Relationship Name**: `member_count`
   - **To Reference**:
     - **Source**: `default`
     - **Schema**: `public`
     - **Table**: `community_member_counts`
   - **Relationship Type**: **Object Relationship**
   - Click **Add New Mapping**, then set **Source Column** to `id` and **Reference Column** to `community_id`. ![The Create Relationship dialog mapping communities.id to community_member_counts.community_id](/images/products/graphql/relationships/table-create-relationship-column-mapping.png)

3. Click **Create Relationship**.

</Steps>

To join on more than one pair of columns, click **Add New Mapping** again for each pair.

## Relate a table to a remote schema

A remote relationship joins a table to a field of a [remote schema](/products/graphql/remote-schemas). The steps assume a remote schema named `rs`, added in <a href="https://app.nhost.io/orgs/_/projects/_/graphql/remote-schemas" target="_blank" rel="noopener noreferrer"><strong>GraphQL → Remote Schemas</strong><span class="not-content" style="display:inline-block;vertical-align:-0.2em;margin-left:.1em"><Icon name="external" /></span></a>, with this query:

```graphql
type Query {
  communityActivity(communityId: String!): CommunityActivity
}

type CommunityActivity {
  uploadsThisWeek: Int!
}
```

<Steps>

1. Open the **⋯** menu next to `communities`, select **Edit Relationships**, and click **Relationship +**.

2. Fill in the **Create Relationship** dialog:

   - **Relationship Name**: `activity`
   - **To Reference**:
     - **Source**: `rs`, under **Remote schemas**
     - **Schema** and **Table**: `N/A`, set automatically
   - **Relationship Details**:
     - Under **Root operation fields** → **Query**, check `communityActivity`.
     - Under **Selected field tree** → **Arguments**, check `communityId`, then set **Fill from** to **Source Field** and **Source field** to `id`. ![The Create Relationship dialog for the rs remote schema with communityId filled from id](/images/products/graphql/relationships/table-create-relationship-remote-schema.png)

3. Check that **Remote field preview**, at the top of **Relationship Details**, shows `communityActivity` with `communityId` mapped to `$id`, then click **Create Relationship**.

</Steps>

To send a fixed value instead of a column, set **Fill from** to **Static Value**.

## Relate a table to another database

If your project connects to more than one database, the **Source** dropdown under **To Reference** lists each one under **Databases**. Because the rows live in a different database, the dashboard saves the relationship as a remote relationship.

For example, to give `communities` the page views stored in a `page_views` table in a database named `analytics`:

<Steps>

1. Open the **⋯** menu next to `communities`, select **Edit Relationships**, and click **Relationship +**.

2. Fill in the **Create Relationship** dialog:

   - **Relationship Name**: `page_views`
   - **To Reference**:
     - **Source**: `analytics`, under **Databases**
     - **Schema**: `public`
     - **Table**: `page_views`
   - **Relationship Type**: **Array Relationship**
   - Click **Add New Mapping**, then set **Source Column** to `id` and **Reference Column** to `community_id`.

3. Click **Create Relationship**.

</Steps>

## Rename, edit, or delete a relationship

Each row under **Relationships** has two buttons:

- <Trash2 size={16} style="display: inline; vertical-align: middle; margin: 0;" /> deletes the relationship from the metadata. The tables and their foreign keys stay.
- <Pencil size={16} style="display: inline; vertical-align: middle; margin: 0;" /> renames a relationship in the same database, for example `communities.community_members` to `members`. Renaming changes the GraphQL field name, so update the queries that use it.

On a remote relationship, the pencil opens **Edit Relationship** instead. There you can change everything except the name. Click **Save Changes** to apply the change.

To change the join of a relationship in the same database, delete it and create it again.

## Define relationships in metadata

Each relationship is stored in the YAML file of the table it belongs to, under `nhost/metadata/databases/default/tables/`. A relationship through a foreign key on the table itself names the column:

```yaml title="nhost/metadata/databases/default/tables/public_community_members.yaml"
table:
  name: community_members
  schema: public
object_relationships:
  - name: community
    using:
      foreign_key_constraint_on: community_id
```

The `communities` file shows the other three shapes. When the foreign key is on the other table, as for `communities.community_members`, the entry names that table as well as the column. A column mapping uses `manual_configuration`, and remote relationships go under `remote_relationships`:

```yaml title="nhost/metadata/databases/default/tables/public_communities.yaml"
table:
  name: communities
  schema: public
object_relationships:
  - name: member_count
    using:
      manual_configuration:
        remote_table:
          name: community_member_counts
          schema: public
        column_mapping:
          id: community_id
array_relationships:
  - name: community_members
    using:
      foreign_key_constraint_on:
        column: community_id
        table:
          name: community_members
          schema: public
remote_relationships:
  - name: activity
    definition:
      to_remote_schema:
        remote_schema: rs
        lhs_fields:
          - id
        remote_field:
          communityActivity:
            arguments:
              communityId: $id
  - name: page_views
    definition:
      to_source:
        source: analytics
        table:
          name: page_views
          schema: public
        relationship_type: array
        field_mapping:
          id: community_id
```

The `activity` and `page_views` entries work only if the `rs` remote schema and the `analytics` database exist, so leave them out if you skipped those sections. Add these keys to the table's existing file. Don't replace the file. Then run `nhost up` to apply the files to your local project. It applies the metadata again even if the project is already running.

### Keep dashboard changes in a local project

In a local project, the dashboard writes to these files only when it saves a change as a migration, as the table form does when you add a foreign key. Relationships you add from a suggestion or with **Relationship +**, and any you edit, rename, or delete, change only the running project. Export the metadata to keep them before you commit:

```bash
nhost dev hasura metadata export \
    --endpoint https://local.hasura.local.nhost.run \
    --admin-secret nhost-admin-secret
```

## Query across a relationship

You select a relationship the same way you select a column. This query returns each community with its members and its member count:

```graphql
query CommunitiesWithMembers {
  communities {
    name
    member_count {
      member_count
    }
    community_members {
      user_id
      joined_at
    }
  }
}
```

If you created the remote schema relationship, select `activity { uploadsThisWeek }` the same way.

You can also filter on a relationship in the same database. This query returns the members of a community named `Engineering`:

```graphql
query EngineeringMembers {
  community_members(where: { community: { name: { _eq: "Engineering" } } }) {
    user_id
    joined_at
  }
}
```

[Permission rules](/products/graphql/permissions/rule-editor) can use relationships too. For example, a rule on `communities` can let a user update a community only when `community_members` has a row with their `user_id`.

## Limitations

- **Edit Relationships** is unavailable for tables and views that aren't tracked in GraphQL, and the menu doesn't show it for functions.
- Suggestions come only from foreign keys between tables in the same database.
- A remote schema relationship can only target fields of the remote schema's `Query` type.
