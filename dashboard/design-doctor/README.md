# Design doctor

Run `pnpm design-doctor generate` after changing theme, ui/v3 components, component barrels, `catalog.meta.mts` or doctor inputs; `pnpm design-doctor generate --check` checks for missing, changed or orphaned artifacts without writing. pnpm 12.3.4 reserves `pnpm doctor` for its built-in health check, hence the script name. `pnpm test:design-doctor` lints, type-checks and tests the generator. Generated files are committed. Default local lint includes doctor sources, but their type-check and tests are opt-in; nix and CI do not include the doctor.

## Baseline and branch checks

`pnpm design-doctor baseline update --seed <rule>` records a new rule (or a version/vocabulary change). Subsequent `baseline update` shrinks counts, never grows them; it drops removed manifest rules with a warning and preserves stale paths unless Git confirms deletion. `baseline move <old src/path> <new src/path>` is the explicit fallback when a rename is not detectable: the old file must be absent and the new file must exist in scope. Branch checks allow the moved entry to consume only counts freed by deleted reference paths for the same rule and subject. Do not edit `baseline.json` by hand. `--check` fails for new findings, invalid suppressions, incomplete coverage, or a baselined rule whose version/vocabulary hash differs from the generated rules (including a rule removed from the manifest). Re-seed changed rules with `baseline update --seed <rule>`; run `baseline update` without a seed to drop removed rules. With `--base`, `--check` also rejects baseline growth. `--changed --base <ref>` uses the merge-base and checks only changed, staged and untracked in-scope sources; an empty set skips Biome and has a null score. It reports a rule newly seeded or version/vocabulary-changed on the branch as “seeded in this PR,” and marks suppressions added since the merge-base on changed files. Git comparisons use `-M`, and an unstaged rename to an untracked exact-content file is carried over without touching the index. If a rename changes content too much, use `baseline move`.

Baseline subjects are keyed by file/rule/subject, not line number. For duplicate subjects the first N findings in source order are baselined; a removed or suppressed finding leaves slack until update. Per-rule `count` shows all detector findings, including suppressed and baselined ones (matching `pnpm lint:design`); `new` and the score exclude suppressions. A duplicate subject removed and re-added in one change cannot be distinguished by count. Serialization sorts keys by code unit before Biome formatting; JavaScript puts integer-like object keys first, which remains deterministic and has no semantic effect. Vocabulary hashes cover the declared detection inputs, not the emitted GritQL predicate: changes to replacement wording, import paths and Button variants do not enable a re-seed. For a predicate-only detection change (such as a CSS-variable exclusion), bump the manifest rule version, regenerate and re-seed that rule. Coverage counts only tracked VCS-ignored files as skipped; ignored files do not make coverage incomplete. The old root-ignore Biome probe is gone because `/logs/` is now anchored and the tracked dashboard logs files are included.

Baseline serialization uses the dashboard's Biome format config. Temp-repo tests that assert identical bytes must copy the root `biome.json` into their isolated root before calling the writer; otherwise Biome's default indentation is tabs. The doctor uses Node >= 22.18 to execute erasable `.mts` syntax without a loader. The workspace still uses `@types/node` ^20, which does not declare all of Node 22's built-in type-stripping APIs: avoid relying on those APIs in the TS sources. Root TypeScript is 5.9.3. The doctor's own tsconfig supplies Node and Vitest types independently of Next.js.

The catalog lists public runtime exports from `ui/v3/*.tsx` and the form/common/presentational `index.ts` barrels. Component metadata uses `@/components/<path>#Export` keys in `catalog.meta.mts`; unknown keys fail generation, and missing descriptions appear under **Undocumented components**. The compiler-API reader follows relative and `@/` barrel re-exports and CVA references. CVA variants and defaults list recipes declared in the component's own module only: imported recipes such as `toggleVariants` in `ToggleGroupItem` and `buttonVariants` in `AlertDialogAction` or `PaginationLink` are not listed. `InputGroupButton` lists its local size recipe but not Button's imported variant recipe. Check the source for those props. When adding a Radix wrapper, check the generated primitive mapping: a Portal/Header may be the first JSX child rather than the wrapped primitive, and namespace destructuring exports need to retain their original Radix names. Radix `Root` exports are also exposed under the bare component name (`Dialog`, not `DialogRoot`); map that name to ui/v3. `dropIn: false` means props/semantics must be checked before replacing raw HTML.

## Tailwind v3 arbitrary-value inventory

When mapping Tailwind v3 arbitrary utilities, `getClassList()` lists concrete generated classes but not `root-[value]` candidates. Probe `createContext(resolvedConfig).candidateRuleMap` for roots with function rules; classify every returned root, fail generation on unmapped roots, and use the parsed value to disambiguate shared roots such as `text` and `border`. The probe currently finds 193 roots, including ambiguous `delay`/`duration`/`ease` roots that need type hints to compile an arbitrary value.

## Biome GritQL gotchas

`biome.design.json` is generated from `manifest.json`: run `pnpm lint:design` from `dashboard/`, not the repository root. Temporary benchmark configs must live in `dashboard/` and be deleted before default `pnpm lint`: a config outside it extending both `biome.json` files by absolute path resolves `vcs.root` against its own directory and skips `dashboard/biome.json` `files.includes`, so generated files get linted. For v1/v2 comparisons, keep the temporary v1 plugin outside `design-doctor/generated/`; `generate` deletes any unlisted file there as an orphan. `root: true`, the root-first pair of `extends`, and `vcs.root: ".."` are necessary for the config chain; plugin paths resolve against the config, but `vcs.root` resolves against the working directory. Plugin `includes` match absolute paths. Plugins in an extended config are retained. On 2.5.11 this two-extends config also re-reports existing `noImportCycles` errors that default lint does not report; the generated opt-in config turns off that one unrelated rule so warning-only design runs exit zero. Grit requires one top-level pattern (use `or { … }` for alternatives), explicit `severity="warn"` on **each** diagnostic, and backtick messages for metavariable interpolation; avoid escaped double quotes in Grit strings. Biome's JSON reporter is experimental and may change with a Biome bump. The parser normalizes double-quoted module-literal subjects (`"x"`) to single quotes (`'x'`) so formatting does not change baseline keys. `--max-diagnostics=none` keeps every finding visible. The fixture harness copies the real config chain and plugins into an isolated dashboard-shaped tree under the OS temp directory to exercise these assumptions. Generator integration tests pass a separate temp config path outside their generated-artifact directory; otherwise tests can rewrite the tracked config or detect the config as an orphan. Use syntax-node kinds for import and re-export specifiers: each specifier matches regardless of list length, whereas snippet `within` (e.g. `import $_ from $source`) matches only a single-specifier import. In combined default + named imports, Biome/Grit can also match an absent optional binding as an empty name; require a nonempty identifier before emitting a diagnostic. Filter node candidates with one anchored `@radix-ui/` source regex before dispatching catalog names, or plugin work on every ordinary import overwhelms the lint budget. Start each branch from its rarest node kind: top-level branches starting at common string literals, identifiers or call expressions scan too many candidates unless a cheap ancestor gates them. For JSX, `JsxAttribute.initializer` includes the leading `=` (`="checkbox"`, `={false}`), while a bare attribute has no initializer. Use `$attrs <: some JsxAttribute(...)` to inspect an element's own attribute list; `contains` also searches inside JSX attribute values and can falsely attribute a nested element's `asChild` or `type` to its parent. To exempt only direct JSX children of `asChild`, match against the parent's `children` using `contains $node until or { JsxElement(), JsxSelfClosingElement(), JsxFragment(), JsCallExpression(), JsArrowFunctionExpression(), JsFunctionExpression() }`; unrestricted `within` also exempts nested descendants or JSX inside a callback. Dispatch JSX tags by name before the `asChild` ancestry check, and share that check instead of repeating it per selector. Biome 2.5.11 can report a Grit runtime failure as an info-level `plugin` diagnostic in otherwise valid JSON with exit code zero; the runner rejects these reports. Its JSON reporter does not list processed file paths: one Biome run emits a verbose summary to stdout for the inventory and JSON diagnostics to a temporary file, then coverage intersects that inventory with manifest-scoped sources, parse/skip diagnostics and VCS ignores. Keep `--reporter=summary` before `--reporter=json --reporter-file=<path>`: the file option binds to the preceding reporter; reversing them mixes stdout, while the file summary uses `ℹ`/`⚠` glyphs that the ASCII stdout inventory parser does not recognize. JSON diagnostics remain the sole source of findings. Keep root ignores anchored (such as `/logs/`) so Biome sees dashboard sources; coverage no longer probes root directory ignores, and omitted expected files still fail completeness. Name saved reporter fixtures something other than `biome.json`: Biome treats that name as a configuration file even inside excluded fixture trees.

The class-site probe is harness-only: it is not in the manifest, `generated/plugins/` or `biome.design.json`. Its diagnostic is at the syntax node for one class site, with all whitespace-separated tokens encoded as subjects. The real message parser expands that diagnostic into one finding per token at the shared site span. The delimiter is U+2028 (a JavaScript line separator, treated as whitespace by the tokenizer even when it occurs in a template chunk); it cannot occur within an extracted token. No token punctuation (`:`, `/`, `!`, brackets or quote characters) needs escaping. Existing single-subject message lines remain compatible. A class rule passes `gateLevels` and `substrings` to `emitClassRule` for cheap, ordered `includes` alternatives on both the site and each token before its regex predicate; `preGate` remains available for specialized Grit predicates. A non-helper call only excludes strings within that call, up to the nearest class context: a surrounding `.map()`, `forwardRef()` or `useMemo()` callback must not hide its nested class sites. Unquoted identifier keys in non-CVA helper objects are class sites (`cn({ italic: enabled })`); keys inside CVA variant maps are ambiguous variant names and must be quoted to qualify. A string used as a computed index, such as `'large'` in `className={sizes['large']}`, is extracted by the shared probe, but `no-unknown-classes` excludes computed-member strings so enum keys such as `MAX_WIDTH[props.maxWidth ?? 'xs']` do not report as classes. The indexed object's values are not followed.

For `no-inline-styles`, start from object-member nodes for property-level spans; a `some` member walk starting at a JSX attribute stops at the first member. Match the member against the enclosing object's `members` field, then check that the JSX attribute's expression is **that same object** (`$obj`), directly or beneath up to three `TsAsExpression`, `TsSatisfiesExpression` or `JsParenthesizedExpression` wrappers. Do not exclude an object with `within JsPropertyObjectMember()` or `within JsSpread()`: `within` walks every ancestor up to the file root, including enclosing render/column definitions unrelated to the style value. It also matches the node itself (`within JsObjectExpression()` would reject every object). A parameterized recursive pattern such as `pattern p($o)` for this identity check overflows the Biome 2.5.11 worker's stack; use fixed-depth wrappers. A separate named recursive pattern can classify the expression's inner AST node without passing an object binding. An `as` assertion's text is not the allowed identifier itself: unwrap it before checking allowed style paths. Do not try to pass a binding *out* of a recursive Grit pattern (`pattern unwrap($capture)` with `as $capture` inside it); that also stack-overflowed the worker. The literal color checker sees static string/template leaves only, and a component import walk is unnecessary for `style` attributes on all JSX elements.

Biome 2.5.11 GritQL details for class rules:

- Biome keeps **one** diagnostic per plugin and syntax span, even if a match registers two different messages. Diagnostics on distinct spans both survive; two plugins can report on the same span. The design doctor therefore splits the token list in the single site diagnostic instead of emitting another warning at the same span. `pnpm lint:design` shows one warning per site and rule listing the tokens.
- A regex-capture `span=$capture` produces a locationless diagnostic; spans must be syntax nodes. A regex capture needs its `($capture)` binding. Grit regexes match the whole node, and `.` excludes newlines: use `[\\s\\S]*` for any text, or include the remainder to capture the first token of a multi-token chunk (for example, `^([^\\s]+)(?:[\\s][\\s\\S]*)?$`). Use `after`/`before JsTemplateElement()` to confirm the chunk edge actually touches an interpolation.
- `split` plus `every` with a named accumulator pattern collects every token; `some` stops at the first, while an inline `$part where { … }` inside `every` retains the first binding. Normalize tabs and line breaks using `join(split($text, delimiter), " ")` before splitting on spaces; Grit strings reject `"\\t"` and treat `"\\u0009"` as a literal escape string, so use a literal tab in the Grit source. Flatten node-text subjects with `join(split(…))` before `register_diagnostic`: a quoted subject containing a newline fails `parseMessage` and makes the runner exit 2.
- A named `class_token` pattern cannot see the outer `$site` binding unless `$site` is explicitly passed as a parameter (`siteAware`). Without that argument, a `$site` exclusion inside the token predicate behaves like an unrelated match, swallowing real findings such as `fake-[10px]`. The shared probe and earlier rules stay on the cheaper, site-independent path.
- `contains` on a `split` list crashes Biome with a stack overflow. Never use it. Matching a helper via `contains` also stops at its first descendant; begin at each candidate site and check its ancestor context, then apply the whole-site gate before the accumulator.
- For each root-kind candidate, Biome evaluates the plugin's entire pattern; extra metavariables cost even on unrelated nodes. Bind names and callees directly in node fields (`JsxAttribute(name=r"…")`, `JsCallExpression(callee=not r"…")`), keep each node-kind alternative's `where` inline in a flat top-level `or`, and avoid top-level named-pattern alternatives (which disable per-kind dispatch). Nest `join(split(…))` rather than binding intermediate whitespace transforms. Cheap ordered site **and** token gates (`includes "-"`, then shade substring alternatives, then family alternatives) reduce raw-palette work without dropping findings.

A glued template interpolation such as `` `w-[${w}px]` `` emits separate chunk fragments (`w-[`, `px]`), so the message parser accepts nonempty, unbalanced fragments instead of rejecting the entire Biome report. The unknown-class rule skips a token only at a template-chunk edge touching an interpolation with no separating whitespace, not by its spelling: `` `${x}-cols` `` and `` `bg-${x}` `` are deferred, while `` `fake-[10px] ${x}` `` is checked. The static-class rule will handle the interpolation. Class token spelling (variants, `!`, opacity and arbitrary syntax) remains intact as the baseline subject. Grit predicates can use `$part <: class_normalized($base)` to check the utility base without its variants, leading important marker or negative prefix; slash opacity is retained. A trailing `!` is invalid in Tailwind v3 and is not normalized or claimed as a raw color; `divide-x-*` and `divide-y-*` are not color utilities in v3. `normalizeClass` is a TypeScript counterpart for suggestions, not a second detector. The Grit accumulator rejoins whitespace-separated fragments between an opening `[` and its closing `]` (including malformed, unclosed brackets) before testing the whole token. It does not fully balance nested brackets containing whitespace after an inner closing bracket; add an explicit fixture and extend the prelude if that syntax becomes necessary. `emitClassRule` also has a whitespace-only fast tokenizer: unknown classes use it with a lazy `[` check, so arbitrary bracket contents containing literal whitespace (rather than underscores) are not joined.

Fixture annotations use `// expect: <rule-id> "<subject>"` on the reported source line (including at the end of the line) or on immediately preceding consecutive comment lines. Inside JSX children, use `{/* expect: <rule-id> "<subject>" */}` instead so the annotation does not become page text; it works before the child or after code on the reported line. A preceding block applies all its annotations to the next source line, with no blank line in between; a final annotation followed only by the file's trailing newline has no following code. Any comment containing `expect:` must match the strict annotation syntax (including spaces and a single annotation per line), rather than silently passing as unannotated source. The harness compares each finding's rule, subject and start line, so both missing and unexpected findings fail, even when counts are unchanged. Fixtures intentionally contain other lint violations (for example, raw buttons without a type), so the full fixture Biome run may exit 1 even when every design diagnostic is a warning. Commit LF fixtures and synthesize CRLF or lone-CR content in the temp tree for newline tests: committed CRLF fails `git diff --check`, and Biome counts lone CR as a line break in diagnostic positions.

Unlike application code, doctor internals use `../` relative imports to make `.mts` sources runnable directly by Node without alias resolution. The scoped Biome override allows this exception; dashboard application imports remain restricted.
