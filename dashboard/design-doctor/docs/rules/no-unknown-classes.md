# no-unknown-classes

This warning finds **static classes and variant names** that Tailwind v3 does not generate in high-confidence class sites (`className`, `*ClassName` and `cn`/`clsx`/`cx`/`twMerge`/`twJoin`/`tw`/`cva`). It checks `getClassList()` from the installed v3 engine, classes defined in `src/styles/*.css`, the `group`/`peer` markers and documented `externalClasses` hooks in `src/grit/rules/no-unknown-classes.mts`. It includes `!`, negative classes, opacity and supported arbitrary-value roots. `pnpm lint:design` displays the token and a link to `pnpm design-doctor`; the doctor gives variant guidance for misspelled variants, or suggests a nearby v3 utility spelling ("did you mean") or a color declaration for unvarianted class findings. A CSS variable alone does not create a Tailwind utility. Suggestions are not guaranteed drop-in replacements.

```tsx
// Warns: unsupported static utilities and a misspelled variant
<div className="flex-cols rounded-huge text-md w-xl bg-brand hovr:flex" />
// OK: v3 utilities, declared tokens, CSS selector hooks and dynamic roots
<div className="!text-sm bg-muted/30 prose max-w-[444px] group/cell" />
```

## Accuracy limits

Static and parameterized variants are inventoried from `getVariants()` in the generator; every segment in a chain is checked, so unknown variants such as `hovr:flex`, `focus-vsible:ring-2` and `md:hovr:flex` generate no CSS and are reported. Use an existing variant or register one via a plugin / `addVariant` in `tailwind.config.js`; regenerate after configuration changes. Valid `xs+:flex-row`, `group-hover/cell:opacity-100`, `aria-selected:text-primary`, `data-[state=open]:flex` and `[&:hover]:flex` pass. The base **after a valid variant is not checked** (`hover:flex-cols` passes); invalid variants still report even when the base belongs to `no-raw-colors` or `no-arbitrary-values`. Arbitrary CSS properties such as `[mask-type:alpha]` are not validated here. Negative forms are normalized against the positive v3 vocabulary; an otherwise known but non-negatable utility such as `-bg-primary` may pass even though it generates no CSS. Tokens already reported by `no-arbitrary-values` are excluded, even ambiguous `duration-[…]`, `delay-[…]`, `ease-[…]` values that may compile to no CSS in this config; valid CSS-variable values are permitted. Every palette class owned by `no-raw-colors` is already in the v3 class list and so does not report twice. Only template-chunk edge tokens touching an interpolation without whitespace are deferred to `require-static-classes` (whether the interpolation precedes or follows the token, as in `` `${x}-cols` ``, `` `bg-${color}` `` or `` `w-[${width}px]` ``). A token followed or preceded by whitespace remains checkable regardless of spelling, including `` `fake-[10px] ${x}` ``. Class sites containing bracketed text with literal whitespace are skipped by this fast tokenizer, including any other classes in that site; use underscores inside arbitrary values. This is a static source check: conditional paths, non-helper variables and runtime-computed classes cannot be verified. Literal strings in computed member expressions are excluded, rather than treating an enum or object lookup key as a class.

`externalClasses` is for real third-party hooks or project selector markers, **never** a way to conceal a dead class; every entry requires a reason. Existing unsupported classes remain visible in the [full finding inventory](../../tests/unknown-classes-audit.md). The [fixed-seed review](../../tests/unknown-classes-audit.md) checks 30 findings for false positives.
