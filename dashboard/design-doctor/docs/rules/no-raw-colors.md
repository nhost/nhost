# no-raw-colors

Use declared dashboard color tokens instead of Tailwind's 22 palette families, `white` or `black`. This rule also checks literal `fill`, `stroke`, `color`, `stopColor`, `floodColor` and `lightingColor` on native JSX elements. It does not judge colors inside arbitrary values (that is the `no-arbitrary-values` rule), dynamic SVG props, or strings outside class sites. `transparent`, `current`, `inherit` and SVG `none` are allowed. A declared color can have a direct hex value; `github` is currently invalid because its declaration contains a trailing semicolon.

```tsx
// Warns: palette colors
<div className="hover:!bg-blue-500/30 text-white" />
cn({ 'bg-blue-500': active });
// Warns: literal paint
<svg fill="#f00" stroke="red" />

// OK here: declared tokens and deferred paint; no-unknown-classes checks unknown static bases
<div className="bg-primary text-primary-foreground bg-brand-missing" />
<svg fill="currentColor" stroke="none"><path fill="url(#gradient)" /></svg>
<svg fill="hsl(var(--primary))" stroke="hsl(var(--primary))" />
```

Use the [generated tokens](../../generated/tokens.md) to choose an existing token. Run `pnpm design-doctor` for OKLab-nearest suggestions; they are **nearest, not exact**, and preserve variants, important modifiers and opacity. Verify contrast in both light and dark themes. `pnpm lint:design` shows the raw subject and a pointer to the doctor, not computed suggestions. If no token fits, define the token under `theme.extend.colors` in `tailwind.config.js` (Tailwind **v3**, not `@theme`/`--color-*`), and if it uses `hsl(var(--name))`, define the CSS variable in `src/styles/globals.css` for the needed themes. Then run `pnpm design-doctor generate`. A CSS variable by itself does not create a Tailwind color utility. For SVG, use `currentColor` with a text token class when paint should inherit. `var(--name)` is allowed for a CSS variable containing a complete color; dashboard HSL channel variables need `hsl(var(--name))` instead. A direct hex-valued Tailwind token does not necessarily define a CSS variable of the same name. No suggestion promises a safe drop-in replacement.

`claimedByRawColors` claims exactly the palette family shades plus `white` and `black` color utilities with supported Tailwind v3 modifiers. A leading `!` is supported, but a trailing `!` (Tailwind v4 syntax) and `divide-x-*` / `divide-y-*` palette classes are not generated by Tailwind v3 and are not claimed. Undeclared color-shaped utilities (for example, `bg-brand-missing`), and unrelated unknown classes, belong to `no-unknown-classes`; that rule skips exactly the tokens claimed here and gives color-aware v3 declaration guidance for unknown color utilities. Detection is limited to class sites described in the [README](../../README.md), complete palette values, and static JSX string attributes. The [fixed-seed audit](../../tests/raw-colors-audit.md) records all 30 sampled real findings and their verdicts (0 false positives).
